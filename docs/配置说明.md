# ImmortalWrt N1 配置说明

## 1. 网络默认值

| 项目 | 默认值 |
| --- | --- |
| N1 地址 | `192.168.128.3/24` |
| 网关、主路由 DNS | `192.168.128.2` |
| DHCP | 关闭 |
| LuCI | HTTP `8080`，HTTPS `8443` |
| Nginx | HTTP `80`，HTTPS `443` |
| 时区 | `Asia/Shanghai` |

N1 默认作为旁路由使用：主路由负责拨号、DHCP 和外网出口，N1 提供代理、反向代理、文件服务和组网服务。地址冲突或网段不一致时，修改 `N1/files/etc/config/network`。

## 2. 文件和构建模块

| 文件或模块 | 作用 |
| --- | --- |
| `N1/.config` | 固件目标、内核模块、驱动和基础软件包。 |
| `N1/diy.sh` | 下载第三方插件、替换主题并写入插件选择；25.12 使用 Go 27.x 和 OpenList 4.2.9，24.10 保留原生 Go 并使用兼容该工具链的最新 OpenList 4.1.10。 |
| `N1/files` | 覆盖固件中的默认网络、DHCP、系统、uhttpd 和首次启动配置。 |
| `N1/files/etc/config/nginx_manager` | Nginx 管理器的安全默认值：上传大小、超时、压缩、TLS 会话和安全响应头。不会创建未知域名的反代站点。 |
| `N1/files/etc/uci-defaults/90-n1-services` | 首次启动启用 irqbalance、Nginx，并生成 Wi-Fi 配置后保持无线关闭。 |
| `.github/workflows/openwrt-builder.yml` | 构建 24.10/25.12、打包 N1 镜像、构建 Docker 镜像和清理旧 Release。 |
| `.github/workflows/update-checker.yml` | 检查 25.12 上游更新并触发双版本构建。 |
| `docker/make_docker_image.sh` | 从唯一 rootfs 产物生成 Docker rootfs，移除硬件和嵌套 Docker 组件；真实 N1 固件仍保留 Docker/Dockerman。 |
| `docker/Dockerfile` | 用 rootfs 构建 ARM64 镜像，入口为 `/sbin/init`。 |

## 3. 内置程序用途

### Amlogic

提供 N1 启动、内核和固件相关支持。只应在真实 N1 固件中使用，Docker 打包时会移除。

### Nginx 和 Nginx Manager

Nginx 是公网 HTTPS 入口，Nginx Manager 用 LuCI 管理站点、证书、日志和配置。项目只预置通用安全参数，不预设域名和后端地址。

创建反代站点：

1. 进入“服务 → Nginx Manager → Sites”。
2. 新建“反向代理”站点。
3. 填写域名和后端地址，例如 `http://127.0.0.1:5244`。
4. 需要 HTTPS 时添加证书并监听 `443`。
5. 保存后由管理器执行 `nginx -t`，测试通过才重载。

上级路由器还必须将 TCP `80/443` 转发到 `192.168.128.3`。不要把 LuCI `8080/8443` 转发到公网。

### OpenList

用于文件管理和 WebDAV。默认端口为 `5244`，建议只监听内网，并通过 Nginx 的 HTTPS 域名反代。WebDAV 的具体路径和存储目录在 OpenList 页面配置，不能在固件中猜测。

### HomeProxy

基于 sing-box 的代理平台，支持客户端、服务端、TLS、透明代理和策略路由。项目只编译并安装 LuCI，不写入 VMess 端口、UUID、证书或防火墙规则。首次使用时在“服务 → HomeProxy”按实际节点配置，避免空配置启动失败或意外暴露代理端口。

### DDNS-Go

负责动态域名更新和证书相关任务。域名证书的实际保存路径以 DDNS-Go 配置为准；需要给 Nginx 或 HomeProxy 使用时，应在对应页面明确填写证书和私钥路径。

### EasyTier

用于虚拟组网。项目不预置网络名称、密钥、虚拟地址、出口节点或转发规则。启用后根据实际组网网段配置接口、防火墙和到 LAN/WAN 的转发。

若希望 VMess 客户端访问 EasyTier 子网，必须同时配置：

1. HomeProxy 服务端入站和客户端路由规则。
2. EasyTier 的实际虚拟网段和接口路由。
3. OpenWrt 防火墙区域及转发。

仅安装两个插件不能自动保证该流量路径。

### Wi-Fi

固件包含 N1 可能使用的 Broadcom/mac80211 驱动和无线工具，但首次启动会将无线设备和接口设置为 `disabled=1`。启用前应在 LuCI 中确认芯片、国家码、SSID、加密方式和信道。

### Docker 管理器

N1 固件两个版本都保留 `luci-app-dockerman`、Docker、containerd 和 Docker Compose，便于在真实 N1 上运行其他容器。24.10 使用上游默认 Go 1.23 工具链，OpenList 固定为仍兼容该工具链的最新 4.1.10；OpenList 4.2.x 要求 Go 1.24 或更高，因此不能在不替换全局 Go 的前提下使用。25.12 使用 Go 27.x 和 OpenList 4.2.9。制作 OpenWrt Docker 镜像时才会删除 dockerd、Dockerman 和 Docker 管理文件，避免容器内嵌套 Docker。

## 4. Docker 镜像检查结论

该镜像可以作为 ARM64 OpenWrt 用户态容器运行，但不是 N1 硬件模拟器。`/sbin/init` 作为 PID 1 启动 procd；网络、防火墙、挂载和部分服务通常需要：

```bash
docker run -d --name immortalwrt-n1 \
  --privileged --network host \
  1911086027/openwrt_cortex-a53:personal-25.12
```

如果只运行 Nginx、OpenList 等普通服务，可改用自定义网络和显式 `-p` 映射；如果需要 OpenWrt 防火墙、策略路由或透明代理，建议使用 `--privileged --network host`。

Dockerfile 不负责：

- 自动把端口发布到宿主机或公网
- 自动配置上级路由器端口转发
- 在容器内运行 dockerd
- 提供 N1 的硬件驱动和 Wi-Fi

## 5. 双版本发布

Actions 使用矩阵构建：

| 源码分支 | Docker 标签 |
| --- | --- |
| `openwrt-24.10` | `personal-24.10` |
| `openwrt-25.12` | `personal-25.12` |

GitHub Release 标签格式为 `OpenWrt_24.10_时间` 或 `OpenWrt_25.12_时间`，从标签即可区分源码版本。不再发布 Docker `latest`、分支原名或 SHA 标签，避免用户误拉取未指定版本。正式构建前执行 `make defconfig`、下载、编译、N1 打包和 Docker 构建；失败时优先查看对应矩阵任务的失败步骤。
