# ImmortalWrt N1 配置说明

## 1. 项目定位

本项目面向斐讯 N1 的 ARM64 旁路由场景，不包含 PPPoE 和 Wi-Fi 功能。N1 通过网线接入主路由，使用固定地址 `192.168.128.3/24` 提供管理、代理和服务转发。

默认配置适合“主路由负责拨号、DHCP 和外网出口，N1 负责旁路服务”的网络结构。若你的主路由不是 `192.168.128.1`，刷机前必须修改 `N1/files/etc/config/network`。

## 2. 文件逐项说明

| 文件 | 作用 |
| --- | --- |
| `N1/.config` | OpenWrt 目标平台、内置软件包和内核模块选择。 |
| `N1/diy.sh` | 编译时下载第三方插件和 OpenList 所需的 Go 27.x 工具链、写入插件选择、修改主题和默认管理地址。 |
| `N1/files/etc/config/network` | 默认网桥、静态地址、网关和 DNS。 |
| `N1/files/etc/config/dhcp` | 旁路由默认关闭 DHCP、DHCPv6、RA 和 NDP，避免与主路由冲突。 |
| `N1/files/etc/config/system` | 主机名、时区、NTP 和 zram 参数。 |
| `N1/files/etc/config/uhttpd` | 将 LuCI 管理端口改为 HTTP `8080`、HTTPS `8443`，把 `80/443` 留给 Nginx 反代。 |
| `N1/files/etc/config/amlogic` | Amlogic 固件更新、内核分支和 CPU 调频设置。 |
| `N1/files/etc/uci-defaults/90-n1-services` | 首次启动时启用 irqbalance 和 Nginx。 |
| `N1/files/etc/crontabs/root` | 每周执行一次 `fstrim`；不再默认自动重启设备。 |
| `N1/files/etc/opkg.conf` | 软件包架构优先级和 overlay 路径。 |
| `docker/Dockerfile` | 使用编译出的 ARM64 rootfs 创建 Docker 镜像，不声明或负责网络端口映射。 |
| `docker/make_docker_image.sh` | 从编译产物生成 Docker rootfs，并移除不适合容器的硬件、Amlogic 和嵌套 Docker 服务。 |
| `.github/workflows/openwrt-builder.yml` | 编译固件、打包 N1 镜像、发布 GitHub Release 和 Docker Hub 镜像。 |
| `.github/workflows/update-checker.yml` | 定期检查 ImmortalWrt `openwrt-25.12` 分支并触发编译。 |

## 3. 插件与冲突检查

### 已确认不冲突

- `nginx-ssl` 提供 `nginx`，满足 `luci-app-nginx-manager` 的依赖；不能同时选择 `nginx-full`。
- uhttpd 使用 `8080/8443`，Nginx 使用 `80/443`，默认没有端口冲突。
- `luci-app-nginx-manager` 仅管理 Nginx 配置，不会替换 uhttpd。
- OpenList 默认使用 `5244` 且 `allow_wan=0`，不会抢占 Nginx 或 LuCI 端口；启用 WAN 访问时会由自身生成防火墙规则。
- `irqbalance` 只负责多核中断分配，不会与 `autocore` 的 CPU 调频功能重复。
- Docker 镜像制作脚本会移除固件内的 dockerd、dockerman 和 Amlogic 服务，避免在 Docker 容器内运行硬件服务或嵌套 Docker；N1 固件本身仍保留 dockerman。

### 已删除的重复项

- 删除 `luci-app-ddns`，保留 `luci-app-ddns-go`，避免同时维护两套 DDNS 管理界面。
- 删除无效的 Wi-Fi、Broadcom、PPPoE、学校网和未启用插件占位配置。
- 删除默认每周自动重启，避免影响反代、下载和长期运行服务。
- 未同时保留 Alist 与 OpenList，避免安装两个用途重叠的文件列表服务。

## 4. 反向代理和外网访问

Nginx 反向代理只负责“收到请求后转发到内网服务”，不会自动获得公网地址。完整链路需要：

1. 域名解析到家庭公网 IPv4 或 IPv6。
2. 上级主路由将 TCP `80/443` 转发到 N1 的 `192.168.128.3`。
3. LuCI 中进入“服务 → Nginx Manager”，创建站点并填写后端地址，例如 `http://192.168.128.10:8080`。
4. 使用 ACME 申请证书，或导入已有证书。
5. 只开放需要代理的域名，不要转发 `8080/8443` 管理端口。

OpenList 首次安装后默认关闭，进入 LuCI 的“服务 → OpenList”启用并完成存储配置。建议使用 Nginx 将 `https://files.example.com` 反代到 `http://127.0.0.1:5244`，这样证书、域名和公网入口统一由 Nginx 管理。

如果没有公网 IPv4，可以使用 IPv6、端口映射服务或安全隧道。Docker 运行时需要显式映射端口，例如 `-p 80:80 -p 443:443`；当前 Dockerfile 不声明 `EXPOSE`，端口映射完全由运行命令决定。

## 5. 正式构建流程

在 GitHub 仓库的 **Actions → Build ImmortalWrt for N1 → Run workflow** 手动运行。正式构建前会执行 `make defconfig`，它会检查包依赖、冲突和无效配置；随后执行下载、编译、N1 打包、GitHub Release 发布和 Docker Hub 发布。

需要配置的仓库 Secrets：

- `TOKEN`：用于更新检测器触发 `repository_dispatch`。
- `DOCKERHUB_USERNAME`：Docker Hub 用户名。
- `DOCKERHUB_PASSWORD`：Docker Hub Access Token，不建议使用账户主密码。

Docker 镜像标签为 `latest`、`openwrt-25.12` 和当前提交 SHA。构建失败时，先查看失败步骤日志，再根据 `make defconfig` 或编译错误定位具体包。
